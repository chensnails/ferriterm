## 二、按优先级排列的缺口

### P0 —— 需求语义未达，用户能直接感知

**1. XFER-03 A↔B 中继：后端能跑，UI 无入口、也无「中继」标注**
现状：`commands.rs:1093-1119` 按 `source_session` / `target_session` 分别 `resolve_vfs`，`ft-transfer/src/lib.rs:462-515` 在客户端内存里逐块转发（256 KiB），能力成立。
缺口：`TransferPanel.tsx:262-301` 本地窗格写死 `sessionId={null}`，远端只有一个窗格，A→B 无法发起；全仓无 relay/中继 文案与徽标。
做法：远端窗格支持选择一个会话作为「另一侧」，两栏都可切换会话；当源与目标都是远端时，在队列项与传输头上打「经本机中继」徽标（i18n 新增键），并在该项悬浮说明流量翻倍。

**2. XFER-01 并发：写死 6，且暂停任务占着许可**
现状：`ft-transfer/src/lib.rs:12` `DEFAULT_CONCURRENCY = 6`，`lib.rs:118` 落到 `Semaphore`，无设置项。
缺口：并发数不可配；更严重的是 `lib.rs:218-239` 的 permit 在暂停期间不释放，6 个暂停任务即可堵死整个队列。
做法：并发数进设置（1–8，默认 6），改后重建信号量或用 `Semaphore::add_permits` 动态调整；暂停时把 permit 归还、恢复时重新申请，避免队列假死。

**3. XFER-04 队列缺源/目标列**
现状：`TransferQueue.tsx:83` 只渲染 `job.name`，`targetPath` 仅作悬浮提示，`sourcePath` 从不展示；队列无表头。
缺口：无源/目标列、无队列统计。
做法：队列改表格式（名称 / 源 → 目标 / 进度 / 状态 / 操作），窄宽度时降级为两行布局；顶部加「N 进行中 · N 等待 · 总速率」统计条。

**4. XFER-07 同步只有单向，删除确认只是一个复选框**
现状：`SyncDialog.tsx:6,44-48` 方向仅 `upload | download`；`ft-transfer/src/lib.rs:619-626` 的 action 枚举只有建目录/拷文件/删文件/删目录；预览存在（`lib.rs:648-703`）。
缺口：无双向/冲突合并；`SyncDialog.tsx:112-123` 的删除确认是单复选框，点 Apply 即执行，无逐条确认。
做法：先做双向（两侧比对，冲突项单独列出并提供「保留较新/保留本地/保留远端」），删除单独弹出确认清单（可逐条取消），预览上限 200 条改为分页或聚合计数。

### P1 —— 架构性，改动面较大

**5. SFTP-02 远端只能一个窗格**
现状：`TransferPanel.tsx:199-227` 用 `<select>` 在 SSH 会话/挂载点之间切换，双栏固定「本地 + 一个远端」。
缺口：没有「本地 + N 个远端」子标签，不能并排两个远端做对拷（与 P0-1 是同一处改造）。
做法：远端侧加子标签条，每个标签绑定一个会话/挂载，标签可关；当前远端集合随标签切换，A↔B 由「两个远端标签」自然成立。

**6. SFTP-01 传输不是浮动面板**
现状：打开传输即把 `activeId` 切到 `TRANSFER_TAB`（`store.ts:489-503`），终端被隐藏（`App.tsx:177-186`）。
缺口：无「浮在终端上」的形态，也无法在会话内就地打开某个目录。
做法：两种选择——(a) 保持全页视图，接受与 Termora 的形态差；(b) 增加可停靠/浮层形态（成本高，需要布局拖拽与 z-index 体系）。建议先不做，等 P0 完成后再评估。

**7. SFTP-07 编辑器不是独立窗口、保存要手点**
现状：`FileEditor.tsx` 是 Modal；冲突检测有（mtime 比对，`ft-vfs/lib.rs:130-137`），但只有「重载」一条路；保存为手动按钮。
缺口：不是 `WebviewWindow`；无自动上传；冲突无强制覆盖。
做法：先补冲突三选一（重载 / 覆盖 / 另存），自动上传做成开关（默认关），独立窗口留到有第二屏需求时再做。

### P2 —— 已知但可延后

**8. XFER-06 断点只在进程内**
现状：`ft-transfer/src/lib.rs:474-507` 按目标文件现有大小续传，有单测；但作业表在内存，进程退出即丢。
缺口：跨重启不可续；目标文件恰好等长时会被误判完成（`lib.rs:477-480`）；`retry()` 不清零 `transferred`，进度可能虚高。
做法：作业表落 SQLite（与主机同一库），启动时恢复 `pending/paused`；写入前先落 `.part` 标记避免误判；`retry()` 重置计数。

**9. SFTP-03 属主列是裸 uid:gid**
现状：`FilePane.tsx:403-405` 直接显示 `uid:gid`，`VfsEntry`（`api.ts:310-320`）没有名称字段。
做法：远端按 session 缓存 uid→用户名映射（读 `/etc/passwd` 一次），未知时回退数字。

**10. XFER-02 递归复制丢属性**
现状：`ft-transfer/src/lib.rs:585-617` 只复制字节，无 chmod/utimes；符号链接当普通文件读。
做法：目录复制后按源 mode 设置权限、按 mtime 回写；符号链接识别后按链接复制，失败则跳过并记日志。

## 三、建议的落地顺序

1. **队列与并发**（P0-2 + P0-3）：新增设置项、释放暂停许可、队列表格化。纯前端 + 少量后端，风险最低，且立刻改善可观测性。
2. **多远端标签 + A↔B 中继标注**（P1-5 + P0-1）：一次改造同时满足两条需求，是本期最大的一块。
3. **双向同步与删除确认**（P0-4）：后端枚举扩一套 action，前端做冲突与逐条确认。
4. 其余 P1/P2 按需要排。

每项单独提交、单独验证；Rust 侧改动需 `cargo build` 通过，前端需 build + `lint:ui` + i18n 键对齐。
